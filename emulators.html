What this is

An inventory of everything the SM8550 build sets up, kept here because the answer is not obvious from reading the source. The emulator list lives in one 1,558-line recipe of nested conditionals, and which of them apply depends on the device being built.

So this was not read by eye. The recipe's own add_emu_core and add_es_system calls were executed with the device set to SM8550 and the helpers stubbed out, and what came back is what follows. It is what the build wires, not what the file appears to say.

What is under review

The x86 corner

Four packages exist to run software this SoC cannot execute, and between them they carry the heaviest dependencies on the image. steam brings in fex-emu, gamescope, lsfg-vk, nss and networkmanager. wine and heroic launch Windows titles, and box64 is a second translator underneath them.

Steam stays. A large part of the PC library from before the mid-2000s is natively 4:3, and this is one of the few handhelds where those games display the way they were drawn rather than pillarboxed. That is the same argument the rest of this fork is built on, pointed at a different library.

Which leaves a narrower question than the one this section started with.

Two x86 translators. Keeping Steam keeps fex-emu, and box64 does the same job by a different route. One image carrying both is worth understanding before either is defended: whether wine can sit on fex-emu, or whether the two translators cover cases the other cannot.

Branches for hardware that is not here

An earlier version of this page said moonlight pulls in the Rockchip media libraries librga and rkmpp. That was wrong, and wrong in an instructive way: those lines exist in the recipe but sit behind if [[ "${DEVICE}" == RK* ]], so they were never applied here. Reading a recipe's dependency lines without evaluating its conditionals is exactly the mistake this page was built to avoid.

Two dead branches were found while checking. The Rockchip one above, and a moonlight-qt build gated on the architecture being the literal string null, which it never is, so qt6 was never a dependency either. Both are gone, and the package is updated from a pin two years old to v2.7.1.

Where several emulators cover one system

Not waste in itself. A second emulator is often the one that runs the awkward title. But each is a package built, cached and shipped, so it is worth knowing where the stacking is.

n64: mupen64plus + gopher64 + ares + retroarch nds: melonds + retroarch gb, gba, gbc: ares + mednafen + retroarch saturn: yabasanshiro + mednafen + 2 cores psx: duckstation + mednafen + 3 cores

Widescreen assumptions

No 16:9-only emulator has been found, and that is not the same as there being none. The three that shipped 1920×1080 render defaults, Supermodel, Flycast and melonDS, were corrected. Establishing that nothing else assumes a widescreen viewport means reading each emulator's shipped config for this handheld rather than its dependency list, which is a longer pass and has not been done.

Removed

Eight have gone since this page was first written, and seven of them cost nothing to lose. drastic, bigpemu, skyemu, nanoboyadvance and hatarisa were never the default for any system, so the RetroArch core that was the default in each case simply carries on. skyemu is not even gone as an emulator, only as a second copy of one, since skyemu-lr stays. daedalusx64 was 32-bit only, so it appeared in the menu on a 64-bit build without ever being built.

Two took a system with them. touchhle was the only thing that ran ios, and sndio left at the same time as the only package that pulled it in. vita3k was the only thing that ran psvita, and the Vita panel is 960×544, exactly 16:9, so it letterboxed here the way PSP does.

SDL3

Six packages already build against SDL3: ares-sa, armsx2-sa, dolphin-sa, gopher64-sa, rpcs3-sa and xemu-sa.

Moving the rest is not something the recipe can force. It depends on whether upstream supports SDL3 at all. The likeliest next candidates, because upstream has support in tree, are ppsspp-sa, flycast-sa, duckstation-sa and scummvmsa.

Three will never move: drastic-sa is a closed-source binary, pico-8 is proprietary, and bigpemu-sa ships prebuilt.

The 44 systems only RetroArch touches

These have no standalone emulator at all. One libretro core each and nothing else, which makes them the cheapest things on the image and the last place to look for savings.
