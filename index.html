Why PortareOS?

The Retroid Pocket Nova has a screen worth building around: 1280×960, 4:3, 120 Hz. ROCKNIX already provides the foundation, but the Nova shares much of its configuration with the widescreen Retroid Pocket 6.

PortareOS keeps the upstream work and changes the parts that should be Nova-specific: display geometry, emulator defaults, latency, suspend, input and a few rough edges that matter more on a handheld than on a generic Linux target.

Same platform, very different panel
Retroid Pocket 61920 × 1080 in use, 16:9
Retroid Pocket Nova1280 × 960, 4:3, 120 Hz

960p is unusually good for retro games. 240p scales cleanly to 4× and 480p to 2×. For many classic systems, integer scaling can be both pixel-perfect and screen-filling.

4:3 NATIVESettings are chosen for the Nova's panel, not inherited from a 16:9 cousin.
120 HZ ONLYNo synthetic 60 Hz mode for the display stack to pick by mistake.
LOWER LATENCYLess frame buffering and a shorter audio path.
HANDHELD FIRSTSuspend, fullscreen dialogs and controls are treated as core features.

What is different

4:3-native display defaults
Render resolutions are corrected to 1280×960 where needed, and integer scaling is enabled by default for systems whose native height divides cleanly into 960.
120 Hz that stays 120 Hz
The synthetic 60 Hz panel mode is removed, avoiding a mismatch between the panel timing and the display controller.
Lower input latency
The emulator frame queue is reduced from two buffered frames to zero. More work is underway to see whether the compositor can be removed from the path entirely.
Lower audio latency
The audio floor is reduced from 20 ms to 5.3 ms. SDL, RetroArch, mpv and the frontend now use PipeWire directly instead of taking compatibility-layer detours.
Deep suspend
Suspend is enabled for the Nova. Put the handheld to sleep in a game and resume a few seconds later instead of treating every break like a shutdown.
Handheld-sized windows
Standalone emulator dialogs open fullscreen so settings remain reachable on a 4:3 screen. Guide+B closes them.
microSD tuning
The downstream controller work removes the vendor High Speed cap caused by the SDR104 tuning issue. The target is roughly 85 MB/s instead of about 13 MB/s; this is still being validated on-device.
Less baggage
Redundant or poor-fit components are removed where they add maintenance without improving the Nova experience. Dolphin is also kept substantially newer than the inherited build.

Roadmap

Direction, not promises. The goal is simple: make the Nova feel configured before you touch a settings menu.

PlannedEvery emulator configured on arrival
Flash the card, copy over games and start playing. Per-system defaults will favour low latency first, then performance and visuals where they do not cost responsiveness.
In progressMore 4:3 cleanup
Render geometry is fixed, but some bezels, overlays and shader presets still carry widescreen assumptions.
Open questionDirect display access
Test whether standalone emulators can bypass Wayland and use KMS/DRM directly. Best case: one less frame between input and display.
PlannedHandheld-native windowing
Replace the desktop-oriented compositor behaviour with something designed around one fullscreen app, a d-pad and four face buttons.
PlannedButton glyph profiles
Choose the physical button set fitted to the Nova and have menus and supported emulators show matching PlayStation, GameCube, Xbox or Nintendo-style glyphs.
PlannedEasy BFI mode
The Nova has a 120 Hz OLED, while most retro content runs at 60 Hz or below. A simple black-frame-insertion mode can use that extra refresh headroom to reduce perceived motion blur without asking games or emulators to run faster.
PlannedOLED calibration
Users have reported poor colour calibration on the Nova's OLED panel, with some indications that the factory profile may be tuned more like an HDR display than a normal SDR handheld. PortareOS will add a measured, corrected colour profile once the panel has been characterised properly.
PlannedPerformance tuning
GPU operating points, CPU affinity and governor tuning for the harder systems, without trading away the latency gains above.

Getting it

Pre-release software. PortareOS is developed by one person on one Nova. Expect rough edges, read the release notes, and keep a known-good card around.

1. Download a build

Builds live on the GitHub releases page. Use the .img.gz file for a fresh card. The .tar file is for updating an existing PortareOS installation.

Verify the download

Keep the image and its .sha256 file in the same directory, then verify it before flashing:

shasum -a 256 -c PortareOS-SM8550.aarch64-<date>.img.gz.sha256

On Linux, use sha256sum -c.

2. Write the microSD card

Decompress the image and write it with Raspberry Pi Imager, balenaEtcher or another raw-image tool.

Command line: macOS / Linux

Check the target device carefully. dd overwrites whatever you point it at.

gunzip PortareOS-SM8550.aarch64-<date>.img.gz

diskutil list
diskutil unmountDisk /dev/disk4
sudo dd if=PortareOS-SM8550.aarch64-<date>.img of=/dev/rdisk4 bs=4m

On Linux, the card is usually /dev/sdX or /dev/mmcblk0; use bs=4M status=progress conv=fsync.

3. Boot it

Power the Nova off, insert the card, then hold Volume Down while powering on. In the boot menu choose Switch boot mode, confirm with the power button, then boot PortareOS.

If your Nova has no boot menu

The bootloader must be replaced first. Follow the ROCKNIX Nova guide for the current adb/fastboot procedure rather than duplicating it here.

This is the risky step: flashing the wrong bootloader can leave the handheld unable to boot.

Updating later

Put the PortareOS .tar file in a folder named UPD on internal storage or a second card. The frontend detects it, stages the update and applies it after reboot.

Fresh installs must start from a PortareOS image. Do not install a PortareOS update tar over an existing ROCKNIX card; the boot partition labels differ.

Build it yourself 
git clone https://github.com/portare-ch/distribution
cd distribution
make docker-SM8550

Images land in target/. A first build needs a container runtime, roughly 100 GB of disk and several hours.

Credits

PortareOS stands on ROCKNIX, JELOS, LibreELEC, CoreELEC and the emulator, Mesa and Linux projects underneath them. Nearly all of the foundation is their work.

Several SM8550 kernel patches come from pocknix-os by shuuri-labs, including microSD, gamepad MCU and panel refresh-rate work. Authorship remains in the patch headers.

For the upstream project and its documentation, visit rocknix.org. Please keep PortareOS-specific bug reports with PortareOS rather than the ROCKNIX maintainers.
